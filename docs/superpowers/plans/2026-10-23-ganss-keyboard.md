## 第二轮：有线 / 2.4G 传输判别（同日）

- [x] 复现：用户插线且保留接收器时，主界面仍固定显示“2.4G 无线”；实机只读枚举确认同时存在两组复合设备（有线组 Mfg=SONiX：MI_00 键盘集合、FF68/61、FF13/01；接收器组：FF60/61 33B、FF59/61）。
- [x] 根因：`QueryDevice` 只选带“2.4G”的 FF60/61 端点，并把 `Transport` 硬编码为“2.4G 无线”，UI 再按该字段渲染。
- [x] 证据：官方 `config.xml` mode 表定义 USB=产品串 `GS3108T-PRO` + `MI_00`，2.4G=产品串 `GS3108T-PRO 2.4G` + `MI_03`；据此实现双证据判定（MI_00 键盘集合 + FF13/01 或 FF68/61 厂商接口），不单凭“出现 USB 接口”改判。
- [x] 测试先行：`test_ganss_wired_mode.ps1` 先红（缺少 ResolveTransport），实现后同时覆盖有线+接收器、仅接收器、仅有线、只有 FF13 的证据不足、接收器伪装有线、电量端点隔离。UI 回归 `test_ganss_wired_mode_ui.ps1` 验证有线时保留真实电量、药丸为“🔌 USB 有线”、标题不再挂自动生成的 2.4G 后缀，托盘状态也不出现 2.4G。
- [x] 只读实机验证：`ResolveTransport` 对当前 17 个 HID 接口返回“USB 有线”；未向设备写入任何新指令。
- [x] 实机确认（同日）：切到 2.4G 模式且线仍插着时，HID 枚举从 17 个接口降为 9 个，SONiX 有线组（MI_00/FF68/FF13）整体消失，仅剩接收器组；ResolveTransport 返回“2.4G 无线”。判定规则成立，无需 FF13 协议探针。

## 第三轮：有线模式的电量语义（同日）

- [x] 实测：有线模式下向 FF60/61 接收器端点连续发 3 次查询，均为 Write=True / Read=False（800~900ms 无应答）；射频已关闭，接收器不再回报电量。
- [x] 修正：`QueryDevice` 在有线时直接返回 `BatteryPercent=-1` 并跳过无意义的 2.4G 写入；大数字显示“已连接 · 供电中”，最后一次 2.4G 读数通过 `FormatWiredFootnote` 标注为“上次读数（时间）”，无样本时写“2.4G 电量不可读”。
- [x] 测试：逻辑用例覆盖 FormatWiredFootnote 的有历史/无历史两种文案；UI 用例断言有线时不再出现冻结的 100%，且托盘状态不含 2.4G。

## 第四轮：充电位 A/B 抓帧（同日）

- [x] 方法：先停掉主程序避免接收器端点被占用；在 2.4G+线（100%）与 2.4G 拔线两种状态下各抓 3 帧 33 字节应答。
- [x] 结果：两态完全一致 `00 20 01 00 64 00 ... 00 85`，除百分比与校验和外的保留位全为 0；官方 `2052.lan` / `1033.lan` 也没有任何“充电 / Charging / Battery”文案。
- [x] 决策：不新增 ⚡ 充电/供电标识，2.4G 模式只显示实时百分比。满电时充电位可能本就不置位，本结论限定为“当前固件 + 满电样本未观察到充电位”；若日后电量降到 90% 以下可复测，但不得用 100% 或插线状态猜充电。
