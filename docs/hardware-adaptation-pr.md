# 建议 PR 标题

feat: 适配雷柏 VT3、高斯 GS3108T-PRO 与盖世小鸡启明星2

# PR 正文

## 改动

### 雷柏 VT3
- 接入 0x07 状态输入，读取电量、X/Y DPI 与档位；寄存器操作串行，设置后写回读校验。
- 按同一物理 HID 父接口绑定雷柏通道，避免有线/接收器混配；恢复通用接收器的有效鼠标 PID 识别。
- 修正未知电量默认满电、真实 0% 被吞、设置失败仍更新 UI/OSD，以及切换端点时档位缓存越界。

### 高斯 GS3108T-PRO
- 新增 2.4G 电量查询：严格匹配产品名称、05AC:024F、FF60:0061、33 字节 Input/Output，使用官方驱动中的 0x20/0x01 查询与校验和。
- 有线/2.4G 双身份判别：依据官方 `config.xml` 的 mode 表，只有“产品串不带 2.4G 的 MI_00 键盘集合”与“同产品串的 FF13/01 或 FF68/61 厂商接口”同时成立才判 USB 有线；接收器自身也有 MI_00/MI_03，不能只看某个接口就改判。
- 有线模式射频关闭、接收器不再回报电量（实测连续查询 Write 成功但 Read 为空）：显示“已连接 · 供电中”，最后一次 2.4G 读数降级为带时间的“上次读数”脚注，不再把旧百分比冒充实时值。
- 充电状态未接入：2.4G 插线/拔线各抓 3 帧应答完全一致，官方语言文件也无充电文案，因此不显示 ⚡，避免用 100% 或插线状态猜充电。
- 排除高斯共享 Apple VID 引发的重复鼠标条目，修正复合 HID 键盘分类与连接方式。

### 盖世小鸡 启明星2
- 新增 GameSirDeviceHelper：只读 65 字节 `00 01 01` 查询，精确匹配 3537:1098（2.4G）与 3537:100F（有线），FF7A/0001，Input/Output 65 字节。
- 应答原始 [2..7] 为稳定身份，[19] 为电量：0..100 有效，FF 为充电哨兵（不表示 100%），F4 实时按键报告忽略；按设备 MAC 合并有线/无线身份，有线优先。
- 首次仅有 FF 时百分比未知（-1），当前会话已有有效读数则保留；缓存不跨进程持久化，不虚构满电。
- 修复旧通用记录 `HID:3537:1098` 隐藏标记连带删除新品牌卡片的问题：MAC 级唯一身份只认显式 MAC 隐藏，共享指纹不再误伤，同型号多只手柄也不会一起消失。

### 工程约束
- 保持 C# 5.0 / .NET Framework 4.0、Win32 HID P/Invoke、零运行时第三方依赖、UTF-8 BOM；未写键位、灯效或固件。

## 验证

- `cmd.exe /c build.bat` 编译成功；新增/相关回归全部 PASS。
- 实机：雷柏 VT3 接收器 24AE:1412；高斯 GS3108T-PRO 2.4G 05AC:024F（实测 `00 20 01 00 64 ... 85` = 100%）；盖世小鸡启明星2 2.4G 3537:1098（实测 78%）。
- 高斯有线/2.4G 切换：HID 接口 17 ↔ 9，有线组（MI_00/FF68/FF13）随模式出现/消失。
- 完整套件在本机 DSH 沙箱受注册表 ACL、`Assembly.LoadFrom` 路径与真实联网限制；硬件适配相关用例全 PASS，其余失败项与本 PR 无关。

## 已知边界

- 高斯官方驱动并发运行时可能争抢 HID 应答；2.4G 电量在退出官方驱动后验证。
- 高斯目前确认 2.4G 电量百分比，未确认充电标志与蓝牙模式私有协议；有线模式的电量不可读，界面显示“供电中”。
- 雷柏保留单主设备模型，高回报率能力依赖接收器/固件；不把软件回读等同于物理频率测量。
- 启明星2 只读设备信息；未推广到未验证的 3537:2106、蓝牙协议或其他小鸡型号。官方软件并发读取可能竞争应答。
